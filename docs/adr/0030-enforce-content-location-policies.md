# Enforce content location policies

Recordings, code, business data, credentials, and execution evidence may remain exclusively on a desktop or in an enterprise private environment while the control plane stores only permitted metadata, references, and state. Authorized execution nodes process restricted content in its allowed location. The architecture will preserve a path to private and isolated deployment, but the initial internal release validates connected hybrid operation unless one of the three required pilots makes full offline execution a release condition. While offline, a desktop may read and edit locally authorized content and run local recognition, agents, builds, and tests as drafts; shared confirmation and external calls wait for connectivity, and reconnecting must revalidate permission before an offline event queue is merged with explicit conflict handling.
