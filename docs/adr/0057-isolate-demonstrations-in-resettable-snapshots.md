# Isolate demonstrations in resettable snapshots

Customer demonstrations will run in a Demo Mode initialized from a locked product, data, account, integration, presentation, and script snapshot rather than ordinary engagement state. The mode must reset predictably, hide inappropriate internal information, prevent demo actions from contaminating formal enterprise records, classify its data as synthetic, redacted, or specifically approved real data, and export a preparation pack without secrets. Every external dependency is declared as simulated, sandbox, or live; live effects receive explicit warnings and readiness checks, and high-consequence writes require an action allowlist plus individual confirmation and audit. Temporary accounts, data, and permissions expire into a tracked reset, disablement, or deletion action, while audience-specific views and rehearsed offline or simulated fallback paths protect the demonstration from disclosure and dependency failures.
